
> **환경변수는 항상 문자열로 로드된다.**
>
> 타입 변환(bool, int, float, list 등)은 **개발자의 책임**이다.
>
> 이 변환 과정을 자동화하고 구조화하기에 **가장 깔끔한 방법이 Pydantic.BaseSettings** 이다.

---

#### 이유와 세부 설명

|**단계**|**내용**|**비고**|
|---|---|---|
|**1️⃣ OS 환경변수**|운영체제 레벨에서 환경변수는 **문자열(str)** 로만 존재한다.|export DEBUG=true → "true"|
|**2️⃣ dotenv 사용 시**|.env는 단순히 “파일 → 문자열 환경변수 등록” 기능만 한다.|load_dotenv()는 변환 안 함|
|**3️⃣ Python 접근 시**|os.getenv("DEBUG")는 항상 "true" 형태로 반환된다.|bool, int 아님|
|**4️⃣ 변환 책임**|따라서 코드 내에서 직접 캐스팅해야 한다.|_env_bool, _env_int 같은 유틸|
|**5️⃣ 자동화 선택지**|Pydantic.BaseSettings을 쓰면 .env를 읽고 타입 캐스팅도 자동 처리|선언형 + 유지보수성↑|

---

#### 예시 비교

**❌직접 처리 (보일러플레이트 많음)**

```python
import os
from dotenv import load_dotenv

load_dotenv()

DEBUG = os.getenv("DEBUG", "false").lower() in ("true", "1", "yes")
PORT = int(os.getenv("PORT", "8000"))
```

---

#### Pydantic 방식 (권장)

```python
from pydantic import BaseSettings

class Settings(BaseSettings):
    DEBUG: bool = False
    PORT: int = 8000

    class Config:
        env_file = ".env"

settings = Settings()

print(settings.DEBUG)  # True (자동 변환됨)
print(settings.PORT)   # 8000 (int로 변환됨)
```

**장점**

- .env, 시스템 환경변수 둘 다 자동 인식

- 타입 캐스팅 자동화

- 검증(Validation)까지 수행

- IDE 자동완성 + 타입힌트 제공

- 테스트에서도 쉽게 Mocking 가능
